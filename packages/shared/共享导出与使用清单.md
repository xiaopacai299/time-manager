# @time-manger/shared 共享导出与使用清单

## 1. 包定位

`@time-manger/shared` 是 monorepo 中的跨端共享包，目标是把三端共同依赖的内容集中维护：

- 同步算法与同步编排（`SyncEngine`、LWW）
- API 契约（Zod Schema + TypeScript 类型）
- 可复用计算函数（如年热力图）
- 统一版本标识（`VERSION`）

> 入口导出见：`src/index.ts`

---

## 2. 当前导出能力（按类别）

### 2.1 常量
- `VERSION`

### 2.2 同步类型（`types/sync`）
- `TimeRecord` / `DiaryRecord` / `WorklistItemRecord` / `MemoItemRecord` / `WorkYearDigestRecord`
- 以及相关基础同步类型

### 2.3 API 契约（`api-contract/*`）
- 资源 Schema：
  - `TimeRecordSchema`
  - `DiarySchema`
  - `WorklistItemSchema`
  - `MemoItemSchema`
  - `WorkYearDigestSchema`
- Push Body Schema：
  - `PushTimeRecordsBodySchema`
  - `PushDiariesBodySchema`
  - `PushWorklistItemsBodySchema`
  - `PushMemoItemsBodySchema`
  - `PushWorkYearDigestsBodySchema`
- 同步协议 Schema：
  - `SyncPullQuerySchema`
  - `PullResponseSchema`
  - `PushResponseSchema`
- 对应 Payload / Body / Response 类型：
  - `TimeRecordPayload`、`DiaryPayload`、`WorklistItemPayload`、`MemoItemPayload`、`WorkYearDigestPayload`
  - `Push*Body`、`SyncPullQuery`、`PullResponse`、`PushResponse`

### 2.4 同步算法（`sync/lww`）
- `parseIsoMs`
- `lwwServerPush`
- `lwwClientMerge`

### 2.5 同步引擎（`sync/engine`）
- `SyncEngine`
- 相关类型（如 `SyncResult`、资源选项等）

### 2.6 业务计算（`year-work-heatmap`）
- `computeYearWorkHeatmap`
- `YearWorkHeatmapPayload` 等热力图相关类型

---

## 3. 各项目使用分布

### 3.1 server（`packages/server`）

**主要使用点**
- `src/routes/sync.ts`
  - 使用 `Push*BodySchema`、`SyncPullQuerySchema`、`lwwServerPush`
  - 使用 `*Payload` 类型
- `src/createApp.ts`
  - 使用 `VERSION`（健康检查返回）
- `src/routes/mobileRest.ts`
  - 使用 `DiaryPayload`、`MemoItemPayload`、`WorklistItemPayload`
- `src/lib/timeRecordDto.ts`
  - 使用 `TimeRecordPayload`

**作用**
- 统一请求参数校验规则
- 保证服务端与客户端同步契约一致
- 用同一套 LWW 冲突策略处理 push

---

### 3.2 desktop（`packages/desktop`）

**主要使用点**
- `src/sync/SyncProvider.jsx`
  - 使用 `SyncEngine`
- `electron-main.js`
  - 使用 `computeYearWorkHeatmap`

**作用**
- 桌面端同步流程编排（pull/push/水位推进）
- 年统计热力图数据计算复用

---

### 3.3 mobile（`packages/mobile`）

**主要使用点**
- `src/api/apiClient.ts`
  - 使用 `DiaryPayload` / `MemoItemPayload` / `TimeRecordPayload` / `WorklistItemPayload` 类型
- `src/screens/DiaryScreen.tsx`
  - 使用 `DiaryPayload`
- `src/screens/WorklistScreen.tsx`
  - 使用 `WorklistItemPayload`
- `src/screens/MemoScreen.tsx`
  - 使用 `MemoItemPayload`
- `src/screens/AppStatsScreen.tsx`
  - 使用 `TimeRecordPayload`

**作用**
- 用共享类型约束接口返回与页面数据
- 降低端间字段漂移与类型不一致风险

---

## 4. 维护约定（建议）

1. 新增字段先改 shared 契约：先更新 `shared` Schema/类型，再改 server 与客户端。
2. 同步行为改动必须补 shared 单测：重点覆盖 `sync/lww.test.ts`、`sync/engine.test.ts`。
3. 任何使用方改造前先 build shared：
   - `pnpm --filter @time-manger/shared build`
4. 不要在端内重复声明共享 Payload 类型：优先从 `@time-manger/shared` 引入。

---

## 5. 快速命令

```bash
# 构建 shared
pnpm --filter @time-manger/shared build

# 类型检查
pnpm --filter @time-manger/shared typecheck

# 运行 shared 单测
pnpm --filter @time-manger/shared test
```
